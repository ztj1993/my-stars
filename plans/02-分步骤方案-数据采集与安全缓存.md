# 02 - 分步骤方案：数据采集与安全缓存

## 1. 目标与挑战

- **目标**：全量提取目标用户 `ztj1993` 在 GitHub 收藏的所有 Star 仓库元数据，并完整保留 Star 收藏时间（`starred_at`）。
- **挑战与风险**：
  - **速率限制（Rate Limit）**：GitHub API 未认证请求限制为 60 次/小时，已认证（Token）为 5,000 次/小时。
  - **网络抖动与超时**：需要对大体积元数据建立可靠的本地缓存，避免重复发起远程请求。

---

## 2. API 接口与分页设计

### 2.1 接口定义
- **API 端点**：`GET https://api.github.com/users/{username}/starred`
- **请求头配置**：
  - `Accept: application/vnd.github.v3.star+json`：返回结构将同时包含 Star 时间戳与仓库完整对象：
    ```json
    {
      "starred_at": "2026-03-15T12:00:00Z",
      "repo": { ... }
    }
    ```
  - `User-Agent: Mozilla/5.0 ...`：符合 GitHub 客户端合规标准。
  - `Authorization: Bearer <GITHUB_TOKEN>`（可选）：优先读取环境变量，支持高频调用。

### 2.2 批量分页策略
- 设置 `per_page=100`（GitHub API 允许的最大单页尺寸）。
- 对 710+ 个 Star 仓库，仅需发起约 **8 次 HTTP 请求** 即可拉取完毕，完全在未认证 60 次/小时的免费额度内。

## 4. 脚本实现与容错机制

- **脚本路径**：[`scripts/fetch_stars.py`](../scripts/fetch_stars.py)
- **容错与礼貌机制**：
  - 单页抓取加入 `time.sleep(0.5)`，避免瞬时并发触发 GitHub 封锁。
  - 检查响应头 `X-RateLimit-Remaining`，实时打印剩余配额。
  - 遇到异常时优雅记录日志并提示错误原因。
